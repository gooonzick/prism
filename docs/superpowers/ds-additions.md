## Fixes to Keysmith's ds

| File | Fix | Why |
| --- | --- | --- |
| `page.rs` | `Page::build`: the list is `self_stretch()` instead of `w_full()`, so with its `mx(-S2)` it reaches `S2` past the content edge on both sides. | `w_full` plus a negative margin shifted the list left instead of widening it, so rows ended 16pt short of the right content edge, and trailing statuses didn't line up with the filter or the selection line's danger button. Backport note: Keysmith's rows end 16pt short today. |
| `page.rs` | `ListRow`: the name and tags sit in a middle row (`grow`, `min_w(0)`); the name column's floor is its min-content, an invisible `ROW_NAME_MIN` strut (the name and meta lines are pinned over it, so a long meta adds nothing), capped by its full width in the middle (`w_frac(1.0)`, CSS automatic minimum size), instead of `min_w(ROW_NAME_MIN)`. Wide rows lay out as before (gallery and Skills snapshots unchanged). | With a pick checkbox and a `ROW_TRAILING` column, a 244-wide list (the 860 window with the inspector open) could not fit pick + `ROW_NAME_MIN` + trailing, so the trailing status was cut at the pane edge. Now tags give way first, then the name truncates below `ROW_NAME_MIN`; the trailing column keeps its width (Task 5 fix). Backport note: Keysmith's rows have no trailing column, so nothing changes there. |
| `page.rs` | `Page::build`: the segments shrink in their row (`shrink()`). | Narrower than their labels need, the kit's fitted segments share the content width equally and truncate their labels instead of painting past the content edge (Task 5 fix). |
